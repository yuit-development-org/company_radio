### ブランチ運用ルール

本リポジトリでは、作業内容を明確にし、
安全にサイトを更新するためにブランチを分けて管理します。

#### ブランチ命名規則

ブランチ名は以下の形式で作成してください。

`種類/作業内容`

| 種類 | 用途 | 例 |
| --- | --- | --- |
| `feature/` | 新機能・コンテンツ追加 | `feature/add-member-profile` |
| `fix/` | 不具合修正 | `fix/modal-display` |
| `update/` | 放送回・既存情報の更新 | `update/episode-05` |
| `docs/` | ドキュメント更新 | `docs/update-readme` |
| `chore/` | 設定・保守作業 | `chore/deploy-workflow` |

### ブランチ作成ルール

- 原則として、1つの変更目的につき1ブランチを作成する
- 複数のページやファイルを変更する場合でも、目的が同じであれば1つのブランチにまとめてよい
- 目的が異なる変更は、原則として別ブランチで管理する
- 作業ブランチは `main` の最新状態から作成する
- 作業完了後はPull Requestを作成し、レビューを依頼する
　(プルリクメッセージのテンプレは PULL_REQUEST_TEMPLATE.md を使用すること)
- マージ後は作業ブランチを削除する

### 作業フロー

1. 作業開始前に `main` の最新状態を取得する
2. `main` から作業用ブランチを作成する
3. 作業・動作確認を実施する
4. 変更内容をコミットし、リモートへPushする
5. `main` 宛てにPull Requestを作成する
6. レビュー・承認後に `main` へマージする
7. マージ後は作業ブランチを削除する

※ `main` への直接Pushは原則禁止とします。
